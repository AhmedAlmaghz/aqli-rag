# Token Economics and Maintenance

يقدم هذا المستند إطارًا تنفيذيًا لإدارة ميزانية الرموز (Token Budget)، تحسين التكلفة والكمون (Cost & Latency Optimization)، وحوكمة وصيانة أصول السياق (Context Governance) لمنصة **Aqli RAG**. يستكمل هذا الملف ما تم تصميمه في [Context Architecture and Six Context Types](./01-context-architecture-and-six-context-types.md) و[Agent Skills and Retrieval Strategy](./02-agent-skills-and-retrieval-strategy.md) لضمان أداء مؤسسي مستقر واقتصادي لإنتاج الاستعلامات باللغتين العربية والإنجليزية.

---

## 1. ميزانية الرموز وتخصيص النافذة (Context Budgets & Allocation)

نظرًا لأن معالجة النصوص العربية في نماذج اللغات الضخمة تخضع لتضخم الرموز (Token Expansion Ratio يصل إلى `1.6x - 2.2x` مقارنة بالنص الإنجليزي نتيجة الترميز المتعدد البايتات)، تتطلب منصة Aqli RAG ميزانيات سياق صارمة ومُحسّنة لكل نموذج مستخدم في النظام.

### 1.1 تخصيص ميزانية النماذج (Model Token Allocation Matrix)

| النموذج | الغرض والمسؤولية | نافذة السياق القصوى | حد الاستدعاء للطلب (Max Target Input) | ميزانية المخرجات (Max Output Tokens) | ميزة التخزين المؤقت (Prompt Caching) | التكلفة التقديرية (Input/Output per 1M) |
|---|---|---|---|---|---|---|
| **`gemini-3.5-flash-lite`** | إعادة صياغة الاستعلامات، التلخيص السريع، استخراج الكيانات، إعادة الترتيب (Reranking) | 1,000,000 | 16,000 token | 4,000 token | مفعّل للأنماط المتكررة (System Instructions) | ~$0.075 / $0.30 |
| **`gemini-3.6-flash`** | الوكيل الرئيسي (Master Agent)، الاستدلال المعقد، توليد الإجابات النهائية، تنفيذ أدوات MCP | 1,000,000 | 64,000 token | 8,000 token (تصل إلى 16k عند توليد الكود) | مفعّل مسبقًا للرموز النظامية الثابتة (`>32,000 tokens`) | ~$0.15 / $0.60 |
| **`gemini-embedding-2`** | التضمين متعدد الوسائط (النصوص، الصور، المستندات) | 8,192 | 8,000 token / chunk | غير محدد (Vectors: 3072 dims) | غير مطبق | ~$0.02 / 1M tokens |

### 1.2 ميزانية السياق حسب وضع العمل (RAG Mode Budgeting)

توزع ميزانية الإدخال لـ `gemini-3.6-flash` في طلب المحادثة المباشر (المخصص بـ 64,000 الرمز) بناءً على وضع RAG المفعّل في مساحة العمل:

```
[Strict Mode Setup: 64k Tokens]
├── System Instructions & Workspace Policy :  4,000 tokens (6.25%)
├── Dynamic User Context & Agent Skills     :  4,000 tokens (6.25%)
├── Retrieved Document Chunks (Strict Vector): 40,000 tokens (62.5%)  <-- أعلى كثافة للمصادر
├── Conversation History (Compacted)        : 12,000 tokens (18.75%)
└── Safety Buffer & System Overhead        :  4,000 tokens (6.25%)

[Augmented Mode Setup: 64k Tokens]
├── System Instructions & Workspace Policy :  4,000 tokens (6.25%)
├── Dynamic User Context & Active Tools     :  6,000 tokens (9.37%)
├── Retrieved Chunks (Vector + BM25)        : 28,000 tokens (43.75%)
├── Web Grounding Context (Search Results)  : 14,000 tokens (21.87%)
├── Conversation History (Compacted)        :  8,000 tokens (12.50%)
└── Safety Buffer & System Overhead        :  4,000 tokens (6.25%)
```

## 2. قواعد استثناء وتقليم السياق (Exclusion & Pruning Rules)

لحماية النموذج من التشويش (Context Stuffing) وخفض التكاليف غير الضرورية، يتم تطبيق استراتيجية تصفية صارمة قبل تجميع السياق الديناميكي (Dynamic Context Assembly).

### 2.1 المستثنيات الصريحة (Explicit Exclusions)

```
                       ┌────────────────────────────────────────┐
                       │      Incoming Raw RAG Payload          │
                       └───────────────────┬────────────────────┘
                                           │
                                           ▼
                       ┌────────────────────────────────────────┐
                       │ Context Exclusion & Sanitation Pipeline│
                       └───────────────────┬────────────────────┘
                                           │
         ┌─────────────────────────────────┼─────────────────────────────────┐
         │                                 │                                 │
         ▼                                 ▼                                 ▼
┌─────────────────┐               ┌─────────────────┐               ┌─────────────────┐
│ Filter Raw Binary│               │ Strip Oversized │               │ Sanitize PII &  │
│ & Image Base64   │               │ HTML / Style    │               │ Credentials     │
└────────┬────────┘               └────────┬────────┘               └────────┬────────┘
         │                                 │                                 │
         └─────────────────────────────────┼─────────────────────────────────┘
                                           │
                                           ▼
                       ┌────────────────────────────────────────┐
                       │ Optimized Context (High-Signal Output) │
                       └────────────────────────────────────────┘
```

1. **البيانات الثنائية الخام (Raw Binaries & Base64 Inline payloads):**
   * تُستثنى أي بيانات صور أو ملفات معالجة كـ Base64 مباشر داخل نص الـ Prompt. تُمرّر فقط عبر مراجع وسائط `AI SDK 7` الرسمية المتوافقة مع API الخاص بـ Gemini.
2. **وسومات HTML والتنسيق الفائق (Verbose HTML / CSS / Formatting):**
   * عند جلب صفحات الويب أو المستندات، يُنفّذ تجريد تام لوسومات HTML، الأنماط، ومخططات السكريبتات، وتحويل المحتوى إلى Markdown نظيف (Clean Semantic Markdown) قبل التقسيم التضميني.
3. **أدوات MCP غير المفعّلة للمحادثة الحالية (Unused Tool Schemas):**
   * يُمنع تحميل جميع مخططات أدوات MCP المسجلة في المنصة داخل Prompt المحادثة. يُحمّل فقط مخطط الأدوات المرتبطة بالوكيل الحالي أو المطلوبة عبر الـ Query Intent Classifier.
4. **بيانات الاعتماد والأسرار (PII & Credentials):**
   * كشف وتعمية تلقائية لمفاتيح API، كلمات المرور، وأرقام الهويات المؤسسية باستخدام طبقة مطابقة أنماط (Regex Scrubbing) قبل إرسال السياق للنماذج الخارجية.

### 2.2 تحسين النصوص العربية (Arabic Context Optimization)

تطبق منصة Aqli RAG خوارزمية تنظيف وتطبيع خاصة بالنص العربي للحد من التضخم غير المبرر في عدد الرموز:

* **إزالة التشكيل غير الضروري (Diacritics Stripping):** إزالة الحركات (فتحة، ضمة، كسرة، تنوين) من نصوص المراجع المسترجعة باستثناء الحالات التي يؤثر فيها غياب التشكيل على المعنى القانوني أو الطبي.
* **إزالة الكشيدة والتطويل (Kashida Removal):** حذف حرف التطويل (`ـ`) المستخدم في التنسيق الجمالي للنصوص العربية.
* **توحيد المترادفات المساندة:** دمج العبارات التمهيدية المكررة في التعليمات البرمجية لتوفير الرموز الثابتة.

## 3. توجيه النماذج واقتصاديات التشغيل (Model Routing & Cost Optimization)

لتجنب استهلاك النماذج الكبيرة في مهام بسيطة، تعتمد المنصة موجهًا آليًا (Smart Model Router) يعتمد على تصنيف تعقيد المهمة (Task Complexity):

### 3.1 جدول توجيه المهام (Task Routing Matrix)

| نوع المهمة | النموذج الموجه | سبب التوجيه | استراتيجية التحسين (Optimization SLA) |
|---|---|---|---|
| **إعادة صياغة السؤال وتوليد الاستعلامات الهجينة** | `gemini-3.5-flash-lite` | مهمة منخفضة التعقيد وتتطلب زمن استجابة < 200ms | تنفيذ مباشر مع استخدام التخزين المؤقت للتعليمات |
| **استخراج الميتابيانات والتصنيف الآلي (Auto-tagging)** | `gemini-3.5-flash-lite` | تعتمد على مخرجات مهيكلة (JSON Schema) ذات تكلفة منخفضة | معالجة دفعات (Batch Processing) غير متزامنة |
| **إعادة ترتيب النتائج (Reranking & Fusion)** | `gemini-3.5-flash-lite` | مقارنة النص المسترجع بالاستعلام الأصلي | تقليم النصوص المقارنة إلى أول 200 كلمة لكل قطعة |
| **المحادثة والاستدلال متعدد الخطوات (Master Agent)** | `gemini-3.6-flash` | يتطلب فهمًا عميقًا لسياق RAG والتخطيط واستدعام الأدوات | استخدام Context Caching للـ System Prompt المستقر |
| **تنفيذ الكود والتحليل المالي/الاحصائي (Sandbox Code Exec)** | `gemini-3.6-flash` | يطلب توليد كود دقيق وتصحيح الأخطاء الذاتي | تقييد عدد محاولات التصحيح الذاتي إلى 3 محاولات |

### 3.2 سياسة التخزين المؤقت للسياق (Gemini Context Caching Policy)

تستفيد المنصة من ميزة التخزين المؤقت المتقدمة لـ Gemini لتقليل التكلفة بنسبة تصل إلى **75%** وتخفيض الكمون للطلبات المتكررة:

* **الحد الأدنى للتفعيل:** يتم تفعيل Caching عند وصول السياق الثابت (System Prompt + Workspace Rules + Core Skills) إلى `32,000 tokens`.
* **مدة البقاء (TTL):** تُحدد مدة البقاء الافتراضية للذاكرة المؤقتة بـ **60 دقيقة**، وتتجدد تلقائيًا مع كل استعلام جديد من نفس مساحة العمل.
* **المستوى المفهرس:** يتم تخزين تعليمات النظام ومصادر المعرفة الأكثر استخدامًا في مساحات العمل الكبيرة (Enterprise Workspaces) كطبقة سياق ثابتة cached prefix.

## 4. ملكية السياق، المراجعة وإدارة الإصدارات (Context Governance & Maintenance)

ضمان جودة الاستجابات يتطلب حوكمة دقيقة لأصول السياق مع مراجعة دورية لمنع تدهور الأداء (Context Decay).

### 4.1 مصفوفة المسؤوليات وحوكمة السياق (RACI Matrix)

| أصل السياق (Context Asset) | المالك (Accountable) | المنفذ (Responsible) | الاستشارة (Consulted) | المطلع (Informed) |
|---|---|---|---|---|
| **توجيهات النظام (`AGENTS.md` / System Prompts)** | مهندس الذكاء الاصطناعي (AI Architect) | مهندس المطالبات (Prompt Engineer) | فريق المنتج (Product Team) | المطورون (Dev Team) |
| **قواعد أدوات MCP ومخططاتها** | مهندس Backend | مهندس التكامل (Integration Eng) | مهندس الأمان (Security Eng) | فريق الذكاء الاصطناعي |
| **فهارس التضمين وإعدادات pgvector** | مهندس قواعد البيانات (DBA) | مهندس RAG / Data Eng | AI Architect | DevOps |
| **ملفات ذاكرة الجلسات والتكثيف** | مهندس Backend | مهندس AI SDK | Prompt Engineer | فريق QA |

### 4.2 دورة حياة صيانة السياق وتكثيف الذاكرة (Memory Compaction Cadence)

```
[نشاط المحادثة المستمر]
        │
        ├── كل 10 جولات (Turns) أو عند بلوغ 16,000 الرمز للمحادثة
        │       ▼
        ├── [عملية التكثيف الضمني - Memory Compaction]
        │       ├── استخدام gemini-3.5-flash-lite لاستخراج الحقائق والقرارات الأساسية
        │       ├── تحويل سجل المحادثة القديم إلى ملخص تنفيذي (Executive Summary)
        │       └── استبدال السجل التفصيلي بالملخص في السياق النشط
        │
        └── كل 30 يومًا على مستوى مساحة العمل
                ▼
        ├── [مراجعة تدهور السياق - Context Decay Review]
                ├── تحليل السجلات (Audit Logs) لمعرفة المقاطع المفهرسة غير المستدعاة
                ├── أرشفة المقاطع ذات جودة الاسترجاع المنخفضة (Low Similarity Hits)
                └── تحديث إصدارات أدوات MCP وقواعد الوكلاء
```

### 4.3 إدارة إصدارات السياق (Context Versioning Practices)

تُعامل أصول السياق وتوجيهات النظام معاملة البرمجيات (Context-as-Code):

1. **الترقيم الدلالي لإرشادات الوكلاء (Semantic Versioning):**
   * تستخدم إرشادات الوكلاء صيغة الترقيم `vX.Y.Z` (مثال: `v1.2.0-agent-legal`).
   * **MAJOR (X):** تغيير جذري في نمط الاستدلال أو تبديل النموذج الأساسي.
   * **MINOR (Y):** إضافة مهارات جديدة، أدوات MCP، أو تعديل طريقة عرض الاستشهاد.
   * **PATCH (Z):** تحسينات طفيفة على صياغة الـ Prompt لتفادي الهلوسة.
2. **سجل التغييرات التلقائي (Change Log):**
   * يُحفظ كل تغيير في تعليمات النظام أو المهارات داخل repository تحت مجلد `.github/context-history/` مع ربطه ببيانات تقييم الأداء (Eval Scores).
3. **التراجع التلقائي (Rollback Criteria):**
   * يتم التراجع الفوري لإصدار السياق السابق إذا ارتفعت نسبة الهلوسة أو الانحراف عن المصادر (Groundedness Failure Rate) بمقدار `> 3%` في اختبارات التقييم المستمرة.

## 5. معايير القبول وشيكليست التحقق (Acceptance Criteria & Verification Checklist)

لضمان الالتزام باقتصاديات الرموز ومعايير الصيانة، يجب تحقيق شروط القبول التالية في البيئة الإنتاجية:

### 5.1 قائمة التحقق التنفيذية (Verification Checklist)

- [ ] **الالتزام بميزانية الرموز:** لا يتجاوز أي طلب موجه لـ `gemini-3.6-flash` حد الـ 64,000 رمز إدخال في جميع الأوضاع (Strict, Augmented, Open).
- [ ] **تحسين الرموز العربية:** تطبيق خوارزمية تنظيف النصوص العربية وتجريد التشكيل والكشيدة، مما يحقق خفضًا لا يقل عن 15% في استهلاك الرموز للنصوص المسترجعة.
- [ ] **فعالية التوجيه (Routing Accuracy):** يتم توجيه 100% من استعلامات إعادة الصياغة والتراكيب والتصنيف إلى `gemini-3.5-flash-lite`.
- [ ] **تفعيل التخزين المؤقت (Caching Ratio):** نسبة استخدام Prompt Caching في طلبات مساحات العمل المؤسسية تتجاوز 40% من إجمالي رموز الإدخال الثابتة.
- [ ] **عزل البيانات والتنقية:** غياب تام لأي مفاتيح أسرار أو بيانات ثنائية خام (Base64) أو وسومات HTML غير ملائمة داخل الـ Prompts المرسلة للنماذج (تم التحقق عبر Audit Logs).
- [ ] **تكثيف الذاكرة (Memory Compaction):** يتم تلخيص وتكثيف محادثات المستخدم التلقائيًا عند الوصول إلى 10 جولات بدون فقدان القرارات أو المفاهيم الأساسية المذكورة.
- [ ] **إدارة الإصدارات:** جميع وكلاء المنصة وأدواتهم موثقة بـ SemVer ومعرفة داخل سجلات تتبع الأداء.
