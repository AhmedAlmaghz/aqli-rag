# منصة **Aqli RAG** — نظام استرجاع وتوليد هجين ثنائي اللغة (عربي/إنجليزي) بمعمارية Multi-Tenant وSaaS-Ready

فيما يلي وصف معماري وتقني احترافي شامل لتطبيق RAG الهجين الذي طلبت بناءه، مبني على أحدث ما هو متاح فعليًا من تقنيات حتى تاريخه.

---

## 1. الفكرة والمبدأ التصميمي

المنصة نظام **RAG هجين (Hybrid RAG)** بمعنى أن كل مساحة عمل (Workspace) يمكنها العمل بثلاث أوضاع قابلة للتبديل لحظيًا من الإعدادات:

- **Strict Mode (مقيّد بالمصادر)**: الإجابة تُبنى حصرًا على المصادر التي جلبها المستخدم في قاعدة معرفته، مع رفض الإجابة أو تنبيه المستخدم عند عدم كفاية السياق (Groundedness Guard).
- **Augmented Mode (هجين)**: تُستخدم بيانات المستخدم كسياق أساسي (Grounding)، ثم يُسمح للنموذج بالبحث في الويب (Web Grounding/Search Tool) لسد الفجوات، مع تمييز واضح في الواجهة بين "من مصادرك" و"من الويب".
- **Open Mode**: الوكيل حر تمامًا يستخدم أدوات الويب والـ MCP الخارجية دون تقييد.

هذا التبديل يتم على مستوى: التطبيق ⟶ قاعدة المعرفة ⟶ المحادثة ⟶ الوكيل الواحد، أي أنه قابل للتخصيص الدقيق (Granular).

## 2. المكدس التقني (Tech Stack)

### الواجهة والتطبيق
- **Next.js 16.2** (App Router) — أحدث إصدار مستقر يضيف تحسينات في الأداء، تصحيح أخطاء أفضل، تحسينات للوكلاء، وأكثر من 200 إصلاح وتحسين في Turbopack، مع نظام تمرير وتركيز محسّن للـ App Router عبر React Fragment refs.
- **React 19.2** مع **View Transitions**، **Activity API** لإدارة الجلسات الخلفية (مفيد لإبقاء محادثة نشطة أثناء التنقل)، و**useEffectEvent**.
- **TypeScript** صارم (strict mode + noUncheckedIndexedAccess).
- **AI SDK 7** (Vercel) — يضيف عمقًا إنتاجيًا لعمل الوكلاء عبر خمسة محاور: تطوير الوكلاء بالتحكم بالاستدلال، سياق الأدوات وزمن التشغيل، دعم الملفات والمهارات من المزود، تطبيقات MCP، وواجهة طرفية، بالإضافة إلى تشغيل الوكلاء مع موافقات الأدوات، والاستمرارية (WorkflowAgent)، والمهلات الزمنية، ودعم الصناديق المعزولة (Sandbox). هذا يجعله الخيار الأمثل لبناء الوكلاء المخصصين ودمج MCP في التطبيق.
- **Tailwind CSS v4 + shadcn/ui + Radix Primitives** لواجهة عصرية، مع دعم RTL/LTR كامل وتبديل تلقائي حسب اللغة.
- **Zustand / TanStack Query v5** لإدارة الحالة والتخزين المؤقت من جهة العميل.
- **next-intl** لدعم التدويل (i18n) العربي/الإنجليزي مع دعم اتجاه الكتابة (RTL) الديناميكي.

### الذكاء الاصطناعي
- **التضمين (Embeddings)**: `gemini-embedding-2` — يدعم إدخالًا متعدد الوسائط، مما يتيح تضمين الصور والفيديو والصوت والمستندات جنبًا إلى جنب مع النص، وتُعيَّن كل الوسائط في نفس فضاء التضمين، بأبعاد 3072 بُعدًا ودعم أكثر من 100 لغة — مثالي للعربية والإنجليزية معًا.
- **الاستدلال (Inference)**:
  - `gemini-3.5-flash-lite`: نموذج منخفض الكمون وفعال من حيث التكلفة، محسّن للتنفيذ عالي الإنتاجية ومنخفض التكلفة لمهام الوكلاء الفرعية وتحليل المستندات — يُستخدم لمهام: التلخيص السريع، إعادة صياغة الاستعلام (Query Rewriting)، إعادة الترتيب (Reranking)، واستخراج البيانات من المستندات.
  - `gemini-3.6-flash`: النموذج الأساسي الذي يقدّم أداءً أفضل في البرمجة والعمل المعرفي والوسائط المتعددة، ويُستخدم كوكيل رئيسي (Master Agent) للمحادثات المعقدة والاستدلال متعدد الخطوات، بينما يعمل Flash-Lite كطبقة تنفيذ سريعة تحته.
  - كلا النموذجين يدعمان نافذة سياق تصل إلى 1 مليون رمز، وحتى 64 ألف رمز إخراج، إدخالًا متعدد الوسائط، والتفكير، واستدعاء الدوال، والمخرجات المهيكلة، والتأريض بالبحث.

### قاعدة البيانات
- **PostgreSQL** (عبر Supabase / Neon / RDS / أي مزود يختاره المستخدم) مع الامتدادات:
  - `pgvector` — تخزين واسترجاع المتجهات (HNSW/IVFFlat) للبحث الدلالي.
  - `pg_trgm` + `fuzzystrmatch` — البحث الضبابي والمطابقة الصوتية، ضروريان لدعم البحث العربي (تشابه الجذور، الأخطاء الإملائية، الهمزات).
  - `pgcrypto` — تشفير الحقول الحساسة (مفاتيح API، بيانات اعتماد الموصلات) على مستوى العمود.
  - `pg_stat_statements` — مراقبة أداء الاستعلامات وتحسين خطط RAG.
  - `uuid-ossp` — معرفات فريدة لكل الكيانات (Workspaces, Sources, Documents, Chunks).
  - `plpgsql` — دوال وProcedures لمهام مثل Hybrid Search (BM25 + Vector + Trigram) على مستوى قاعدة البيانات.
- **Row-Level Security (RLS)** إلزامية على كل جدول، مفعّلة بـ `workspace_id`/`user_id` لضمان **العزل التام بين المستأجرين (Multi-Tenant Isolation)**.

## 3. معمارية عزل المستخدمين والخصوصية

- **Multi-Tenancy على مستوى الصف (Row-Level)** عبر RLS في Postgres + مفاتيح تشفير مشتقة لكل Workspace (Envelope Encryption باستخدام `pgcrypto` + KMS خارجي اختياري).
- **عزل التخزين**: كل Workspace له "دلو" (Bucket/Prefix) منفصل في S3-compatible storage، مع سياسات IAM مولّدة ديناميكيًا.
- **عزل الذاكرة المتجهية**: فهارس pgvector مقسّمة منطقيًا بـ `workspace_id` وفهرسة جزئية (Partial Index) لتفادي تسرّب السياق بين المستخدمين أثناء البحث الدلالي.
- **سجل تدقيق (Audit Log)** شامل لكل عملية جلب/حذف/مشاركة مصدر أو استدعاء أداة MCP خارجية.
- **إدارة الأسرار**: مفاتيح API لكل مزود (Gemini, OpenAI, Anthropic, إلخ) تُخزَّن مشفّرة بـ `pgcrypto` أو في Vault خارجي (Vercel Secrets/Doppler)، ولا تُمرَّر أبدًا إلى الطبقة الأمامية.
- **الامتثال**: دعم تصدير/حذف البيانات (GDPR-style)، وسياسة احتفاظ قابلة للتهيئة لكل مصدر.

## 4. تعدد المزودين (Bring Your Own Everything)

من صفحة **الإعدادات** يختار المستخدم أو مسؤول المساحة:

| الفئة | الخيارات القابلة للتوصيل |
|---|---|
| **مزود الاستدلال/الذكاء الاصطناعي** | Google Gemini (افتراضي)، OpenAI، Anthropic، Mistral، Groq، أو أي نموذج متوافق عبر AI SDK Provider Registry |
| **مزود التضمين** | Gemini Embedding 2، أو بديل آخر (مع تنبيه بضرورة إعادة الفهرسة عند التبديل نظرًا لاختلاف فضاء المتجهات) |
| **مزود معالجة المستندات** | Mistral Document AI أو Unstructured.io (API/MCP) |
| **مزود قاعدة البيانات** | Supabase Postgres، Neon، AWS RDS، أو Self-hosted Postgres (طالما يدعم الامتدادات المطلوبة) |
| **مزود التخزين (Object Storage)** | AWS S3، Cloudflare R2، Supabase Storage، Google Cloud Storage — أي واجهة متوافقة مع S3 API |
| **مزود المصادقة** | Auth.js (NextAuth)، Clerk، Supabase Auth، WorkOS (SSO/SAML للمؤسسات) |

هذا يتحقق عبر طبقة تجريد (Adapter Pattern / Provider Registry) موحّدة في الخادم، بحيث يبقى منطق التطبيق مستقلًا عن أي مزود بعينه — تمامًا كما يوفر AI SDK 7 طبقة موحّدة عبر توحيد الوصول إلى ميزات كل مزود عبر واجهة برمجية موحّدة، مما يلغي الحاجة لأغلفة خاصة بكل مزود.

## 5. مصادر جلب البيانات (Data Connectors)

مكتبة موصّلات قابلة للتوسّع، كل موصّل يعمل كـ Job غير متزامن (Queue-based Ingestion Pipeline):

- **الملفات**: رفع مباشر (PDF, DOCX, PPTX, XLSX, CSV, Markdown, صور ممسوحة ضوئيًا/OCR).
- **الويب**: Web Crawler + Sitemap Ingestion + RSS.
- **التخزين السحابي**: Google Drive، OneDrive/SharePoint، Dropbox، Notion، Confluence.
- **قواعد المعرفة المؤسسية**: Slack، Jira، GitHub/GitLab (Repos & Wikis)، Zendesk.
- **قواعد البيانات الخارجية**: اتصال مباشر (Read-only) بقواعد بيانات العميل عبر Connector API.
- **APIs مخصصة**: عبر Webhooks أو MCP Servers خارجية يضيفها المستخدم من السوق.

### خط أنابيب المعالجة (Processing Pipeline)
1. **الاستخلاص (Extraction)**: يختار المستخدم في الإعدادات بين **Mistral Document AI** (دقة عالية في الفهم البصري للمستندات، جداول، تخطيطات معقدة، عربي/إنجليزي) أو **Unstructured (API/MCP)** كبديل مفتوح المصدر لتقسيم العناصر (Partitioning).
2. **التنظيف والتطبيع (Normalization)**: إزالة التكرار، تطبيع الأحرف العربية (إزالة التشكيل الاختياري، توحيد الألف/الهمزة)، كشف اللغة تلقائيًا لكل قطعة نصية.
3. **التقسيم (Chunking)**: استراتيجية Semantic Chunking + هيكلية (بحسب العناوين/الجداول) مع Overlap قابل للتهيئة، ودعم Chunking خاص بالجداول (Table-aware).
4. **التضمين (Embedding)**: عبر `gemini-embedding-2` مع Batch Processing وقائمة انتظار (Queue) لمعالجة الأحمال الكبيرة.
5. **الفهرسة**: تخزين في `pgvector` (HNSW) + فهرس `pg_trgm` نصي للبحث الهجين (Hybrid Search: Vector + BM25/Trigram + Metadata Filters).
6. **الوسم التلقائي (Auto-tagging/Metadata)**: استخراج كيانات، تصنيف موضوعي، وربط بمصدر أصلي (Provenance) لكل مقطع لأغراض الاستشهاد (Citations) في الإجابات.

## 6. ميزة MCP (Model Context Protocol)

طبقة MCP قوية ثنائية الاتجاه:

- **MCP Server داخلي** يعرضه التطبيق نفسه: يسمح لأي عميل خارجي (Claude Desktop، IDE، تطبيقات أخرى) بالاتصال بقاعدة معرفة المستخدم، تنفيذ بحث، إنشاء مصادر جديدة، أو حتى الدردشة مع وكيل معيّن — كل ذلك محكوم بنفس صلاحيات RLS ونطاق الـ Workspace.
- **MCP Client متعدد**: التطبيق نفسه عميل MCP يتصل بخوادم MCP خارجية (مثل GitHub MCP، Notion MCP، Slack MCP، أو خوادم مخصصة يضيفها المستخدم عبر السوق) لجلب بيانات جديدة أو تنفيذ أدوات أثناء الدردشة.
- استفادة من دعم **MCP Apps** في AI SDK 7، حيث أصبح MCP طريقة شائعة لربط الوكلاء بالأدوات والموارد، لكن ليست كل أداة يجب أن تكون مرئية للنموذج، وبعض خوادم MCP تحتاج لعرض واجهة مستخدم متخصصة إلى جانب أدواتها — يُستغل هذا لعرض نتائج غنية (جداول، رسوم بيانية، معاينات مستندات) داخل واجهة الدردشة مباشرة من استجابة أداة MCP.
- **إدارة الصلاحيات**: كل اتصال MCP خارجي يمر بموافقة صريحة من المستخدم (Tool Approval flow المتوفر في AI SDK 7)، مع سجل استدعاءات كامل.
- **بروتوكول موحّد للمصادر والدردشة**: نفس أدوات MCP يمكن استخدامها كمصدر بيانات (Ingestion) أو كأداة حيّة (Live Tool Call) أثناء المحادثة، حسب تهيئة المستخدم.

## 7. السوق (Marketplace)

قسم مستقل داخل التطبيق يضم:

- **الموصلات (Connectors)**: إضافة مصادر بيانات جديدة (كما في القسم 5).
- **خوادم MCP**: كتالوج خوادم MCP موثوقة (رسمية ومجتمعية) مع تثبيت بنقرة واحدة وتوثيق OAuth عند الحاجة.
- **الوكلاء الجاهزون (Agent Templates)**: وكلاء معدّون مسبقًا لمهام شائعة (باحث قانوني، محلل مالي، مساعد دعم فني، مترجم عربي/إنجليزي متخصص) قابلون للاستنساخ والتخصيص.
- **الأدوات والمهارات (Tools & Skills)**: أدوات مستقلة (حاسبة، منفذ كود، مولّد رسوم بيانية، أداة استخراج جداول) يمكن تركيبها لأي وكيل، مستفيدة من نظام **Skills** الجديد في AI SDK 7 عبر `uploadSkill` الذي يتيح رفع مهارة مرة واحدة ثم استخدام مرجع لها في استدعاءات الاستدلال اللاحقة.
- **التكاملات**: مزودو مصادقة، تخزين، وإشعارات (Slack/Email Webhooks).
- **نظام تقييم ومراجعات** لكل عنصر في السوق، وإصدارات (Versioning) للوكلاء والأدوات المنشورة من المجتمع أو من داخل المؤسسة (Private Marketplace للمساحات المؤسسية).

## 8. الوكلاء والدردشة

- **منشئ الوكلاء (Agent Builder)**: واجهة لإنشاء وكيل مخصص يحدّد له المستخدم:
  - الشخصية والتعليمات (System Prompt) بالعربية أو الإنجليزية.
  - النموذج المستخدم (اختيار حر من المزودين المفعّلين).
  - الأدوات والمهارات المرتبطة به من السوق.
  - خوادم MCP التي يمكنه استدعاءها.
  - نطاق قاعدة المعرفة: تحديد مصادر/مجلدات بعينها فقط يُسمح للوكيل بالبحث فيها (Scoped Retrieval).
  - وضع العمل (Strict/Augmented/Open) كما في القسم 1.
- **محرك الدردشة**: مبني على `useChat`/`Agent` من AI SDK 7 مع:
  - بث الاستجابة (Streaming) عبر Server-Sent Events/HTTP streaming.
  - **WorkflowAgent** للمهام الطويلة القابلة للاستئناف — إذ يوفر وكلاء مستمرين وقابلين للاستئناف يصمدون أمام انقطاع الاتصال أو انتهاء الجلسة (مفيد جدًا لمهام البحث العميق متعددة الخطوات).
  - **موافقات الأدوات (Tool Approvals)** قبل تنفيذ أي إجراء حساس (كتابة، حذف، استدعاء خارجي مدفوع).
  - عرض الاستشهادات (Citations) بشكل تفاعلي، مع روابط مباشرة إلى المقطع/الصفحة الأصلية في المصدر.
  - تبديل الوكيل والنموذج في منتصف المحادثة دون فقدان السياق.
  - دعم الأوامر السريعة (Slash Commands) واستدعاء وكلاء فرعيين (Sub-agents) للمهام المتخصصة (Multi-Agent Orchestration).

## 10. النشر وأفضل الممارسات الهندسية

- **النشر**: Vercel كخيار أساسي (Edge + Serverless Functions، ISR، Vercel Queues/Workflows للمهام الطويلة كالفهرسة)، مع إمكانية النشر البديل عبر Docker/Kubernetes على أي مزود سحابي (البنية مصممة "Platform-agnostic" عبر متغيرات بيئة وProvider Adapters).
- **قوائم انتظار المهام**: معالجة المستندات والفهرسة تتم بشكل غير متزامن (Background Jobs) لتفادي حدود زمن تنفيذ الدوال (Serverless Timeout)، عبر Vercel Queues أو BullMQ/Redis كبديل ذاتي الاستضافة.
- **المراقبة**: تكامل OpenTelemetry (يدعمه AI SDK 7 عبر `@ai-sdk/otel`) لتتبع كل خطوة استدلال، واستخدام `pg_stat_statements` لمراقبة أداء الاستعلامات.
- **الاختبار**: اختبارات وحدة (Vitest)، اختبارات تكامل لخط أنابيب RAG (Retrieval Evaluation)، واختبارات E2E (Playwright) للواجهة ثنائية اللغة.
- **CI/CD**: فحوصات تلقائية للأنواع (TypeScript)، Lint، واختبارات الانحدار على جودة الاسترجاع (RAG Eval Harness) قبل كل نشر.
- **التوثيق**: بنية Monorepo (Turborepo) تفصل الحزم (`ui`, `db`, `ai-providers`, `mcp`, `connectors`) لسهولة الصيانة والتوسّع المستقبلي.
